# Pottinger_ECU — система управления пресс-подборщиком

Самодельная система управления процессом обвязки для пресс-подборщика Pottinger
на базе двух плат Arduino, связанных по RS485.

## Архитектура

```
[ Пульт / Master ]  <---- RS485 (9600, полудуплекс) ---->  [ Пресс / Slave ]
   в кабине трактора                                         на самом прессе
```

- **Master (Пульт)** — панель в кабине: ЖК-дисплей 16×2 (I2C, PCF8574),
  тумблеры режима/сетки-шпагата, кнопки экрана/действия, зуммер. Опрашивает
  Slave каждые 300 мс, отображает состояние процесса и статистику.
- **Slave (Пресс)** — конечный автомат самого процесса обвязки: датчики
  плотности, начала/конца обвязки, двери, реле мотора (сетка/шпагат), реле
  сирены и маячка. Работает полностью автономно даже без подключённого
  пульта.

Обе платы — Arduino на ATmega328P с загрузчиком **Optiboot** (обязательное
условие для корректной работы аппаратного watchdog, см. ниже).

## Структура репозитория

```
Master/
    Master.ino      — код пульта, версия 2.5
Slave/
    Slave.ino        — код пресса, версия 3.2
```

Каждая плата — отдельный скетч в своей папке (имя `.ino`-файла совпадает с
именем папки). **Не держите оба файла в одной папке** — Arduino IDE
компилирует все `.ino` в папке как один файл, и одинаковые имена структур
(`MasterData`, `SlaveData`, `setup()`, `loop()`) в обоих файлах вызовут
ошибки компиляции о повторном определении.

## Ключевые возможности

### Обе платы
- Аппаратный watchdog (`avr/wdt.h`, таймаут 2 сек) — защита от зависаний
  из-за электромагнитных помех от электродвигателя.
- `MCUSR = 0; wdt_disable();` первыми строчками `setup()` — обязательно для
  корректной работы watchdog на новых загрузчиках (иначе унаследованный бит
  `WDRF` держит WDT активным со старым таймаутом и вызывает бутлуп).
- Обмен по RS485 с CRC-проверкой (XOR) каждого пакета.

### Master (Пульт), v2.5
- Управление режимами (авто/ручной, сетка/шпагат), экран настроек с
  редактированием таймаутов пресса, статистика тюков.
- Восстановление шины I2C (`i2cBusRecovery()`) после захвата помехой от
  двигателя — если ведомое устройство (PCF8574 на LCD) зависает
  посреди I2C-транзакции и держит SDA в LOW, обычный сброс МК это не лечит;
  требуется ручная процедура "дотактирования" шины.
- Активная обработка таймаута Wire в `loop()` — при обнаружении сбоя шины
  автоматически восстанавливает её и переинициализирует LCD.

### Slave (Пресс), v3.2
- Конечный автомат: `WAIT_DENSITY → WAIT_TRACTOR → WAIT_START_SENSOR →
  MOTOR_RUNNING_TIMER → WAIT_END_SENSOR → WAIT_DOOR → WAIT_DENSITY`.
- **Умное восстановление после сбоя питания** — контрольная точка процесса
  (0 = камера пуста, 1 = мотор запущен, 2 = тюк готов) хранится во внешней
  EEPROM с инверсной контрольной суммой; при перезапуске автомат
  восстанавливает корректное состояние без повторной обвязки уже готового
  тюка.
- **Сброс цикла через концевик двери** (по заводской схеме Pottinger) — на
  сборках без отдельной кнопки сброса открытие двери во время незавершённого
  цикла интерпретируется как аварийный сброс (мотор глушится, чекпоинт
  обнуляется, тюк не засчитывается). Если цикл уже завершён
  (`currentState == WAIT_DOOR`) — открытие двери работает штатно: выгрузка
  готового тюка со счётом.
- Полная автономность: без пульта работает по тумблеру "сетка/шпагат" на
  самом прессе и заводским таймаутам.

## Известные ограничения / рекомендации по железу

- Помехи от электродвигателя (EMI) — основной источник нестабильности в
  этом проекте. Программные меры (watchdog, восстановление I2C, дебаунс
  датчиков) снижают последствия, но не устраняют причину. Рекомендуется:
  - защитный диод/снаббер прямо на обмотке мотора/катушке реле,
  - экранированная/скрученная проводка I2C и линий концевиков, разнесённая
    от силовых проводов,
  - внешние подтягивающие резисторы (4.7–10 кОм) на критичных линиях
    датчиков вместо/вместе с внутренними pullup,
  - RC-фильтр (1 кОм + 100 нФ) на входах датчиков, наиболее подверженных
    наводкам (в частности — концевик конца обвязки).
- Физическая кнопка аварийного сброса на прессе (`PIN_RESET`) в текущей
  сборке не выведена — соответствующий код (диагностический `TEST_MODE`,
  комбо возврата планки `RETURN_TO_HOME`) присутствует, но неактивен и
  оставлен на случай будущего добавления кнопки.
- Автокоррекция состояния по "зависшим" датчикам (плотности/конца обвязки)
  сознательно не реализована — см. `CHANGELOG.md`, риск повторной обвязки
  поверх уже готового тюка.

## Прошивка

Оба скетча требуют загрузчик **Optiboot** (аппаратный watchdog корректно
восстанавливается после сброса только с ним; со стандартным загрузчиком
плата уходит в бесконечный цикл перезагрузок).
